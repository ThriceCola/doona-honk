# Migrating to v0.1.0-beta.7

Use this page when upgrading from `v0.1.0-beta.6`.
It lists only changes that affect an existing configuration or operator expectation.

## 1. Before you upgrade

| Change | What to do |
| --- | --- |
| `ss` entries that declare a SIP002 plugin other than simple-obfs (`obfs`, `obfs-local`, `simple-obfs`, `simpleobfs`) are now rejected instead of keeping the value as inert metadata. A static configuration fails to load; a subscription entry is skipped on its own. | Remove the plugin, or point the entry at a simple-obfs server. |
| `plugin_opts` without a `plugin` is rejected. | Name the plugin, or delete the options. |
| A share link that used to parse with `plugin=v2ray-plugin` (or any other unsupported name) no longer becomes a plain Shadowsocks node; that entry is rejected. | Remove the query, or import the node through a client that runs that plugin. |
| `ss` entries with simple-obfs now really obfuscate instead of dialing the ciphertext in the clear, so their derived node ID changes and any pin or Score history keyed by the old ID is lost. Entries without a plugin keep their ID. | Re-pin the node if it was pinned. Entries that never connected before now work against a simple-obfs server. |
| The plugin options are validated: `mode` is required and must be `http` or `tls`, `path` is refused with `tls`, unknown option keys are refused, and one option may not carry two different values. | Keep only the options the mode uses; Clash `plugin-opts` accepts the same keys as the SIP002 string. |
| Simple-obfs obfuscates TCP only. Shadowsocks UDP still goes to the node's host and port unmodified, as in dae and Mihomo. | Nothing, unless a rule assumed UDP was obfuscated too. |
